# カキフォイの日記 — 原稿作成用Chatプロジェクトの指示

> **原本はリポジトリの `CLAUDE.md`。この文書はChatで記事原稿と投稿依頼文を作る人向けの要約。**
> **この文書を更新したら、原稿作成に使用するChatGPT・claude.aiのプロジェクトに貼り直すこと。リポジトリの更新だけでは外部プロジェクトへ自動反映されない。**

## 基本情報

## タグのルール

- 既存タグを確認し、**表記ゆれを作らない**（例: ×「牛たん」→ ○「牛タン」、×「Nightreign」→ ○「ナイトレイン」）
- **英語タグは固有名詞の製品・サービス名のみ可**（Discord, iPhone等）。略語・一般概念は日本語に（例: GW → ゴールデンウィーク）
- **地名は市単位**を基本にする（籠原→熊谷、深谷市→深谷）
- 新規タグは「**今後2記事以上で使う見込みがあるか**」で判断。製品型番・一点物の固有名詞はタグにせず本文で表現する
- 子育て系タグは「**子育て**」に統一する
- 宿泊を伴う外出=「旅行」、日帰り=「おでかけ」の使い分け
- **タグは本文に実際に登場する内容のみ**。関連が薄い・本文に出てこない話題のタグは付けない（例: グルメの話が無い記事に「埼玉グルメ」、本の言及が無い記事に「DIE WITH ZERO」を付けない）。迷うタグは依頼文に「（要照合）」と添えてPMに判断を委ねる
- **依頼文のタグ欄には、各タグの根拠（本文のどの話に対応するか）を一言添える**（例: 「節約＝CDレコを買わない判断の話」）。根拠が書けないタグは候補から外す

## 記事原稿の書き方

- **Word・Google Docs・Markdownの原稿を作る前に、この最新版の指示を使う。以前の台本や会話の旧アフィリエイト案内を流用しない。**
- H2見出し（`##`）の先頭に絵文字を1つ付ける（例: `## 🎬 …`）
- 本文中の画像は挿入位置にプレースホルダーで指定: **「【ここに〇〇を挿入】」**
- 動画の埋め込みは: **「【ここに動画を埋め込み：URL】」**
- 記事末尾は、下記の**お礼＋広告開示だけの中立2段落が既定**。Word・Google Docs・Markdownとも、投稿担当が直す前提ではなく、納品する原稿の時点で完成させる
- 全記事共通のグリル・お肉への誘導、カテゴリ・タグによる自動選定、案内未設定・該当商品なしを理由に別商品で穴埋めするフォールバックは禁止。以前の台本・会話・テンプレートから旧販促案内を復活させない
- 商品案内は、対象記事を明示選択し本文との関連性を個別確認した場合だけの任意の例外。登録方法と本文ソースの一致条件は下記「記事別案内」を参照し、未選択の記事は中立2段落のままにする
- 商品に結びつけるために体験・使用感・購入歴を創作したり、本文へ余分な説明を足して関連性を後付けしたりしない。根拠を照合できなければ商品案内を追加せず確認する
- 記事ごとにAmazon指定開示を本文へ重複記載せず、記事冒頭の広告表記と、プライバシー＆免責事項ページのAmazon指定開示を維持する
- 記事末尾の並びは必ず: **本文 →（商品カードがあればカード）→ `---` → 末尾案内**
  （区切り線 `---` は末尾案内のすぐ上に置く）
- 原稿に旧定型文がある場合は、その段落だけを原則として中立2段落へ移行する（明示選択・個別確認済みの記事のみ記事別案内）。これはユーザー承認済みの原稿保持ルールの例外。本文・frontmatter・画像・日付と、既存の有効な本文リンク・商品カード・関連記事・トップページの商品紹介は変更せず、実際のアフィリエイトID・トラッキングURL・PR／広告表記も保持する。既存記事に旧定型文がない場合、この一括移行では末尾案内を新設しない。
- Amazon・楽天のアフィリエイトリンクの利用を支援目的で依頼・推奨しない。紹介商品以外の購入を促す定型誘導も書かない。根拠は[Amazon公式FAQ](https://affiliate.amazon.co.jp/help/node/topic/G8TW5AE9XL2VX9VM)、[Amazon運営規約5条](https://affiliate.amazon.co.jp/help/operating/agreement)、[楽天アフィリエイトガイドライン](https://affiliate.rakuten.co.jp/guideline/rule/)。記事冒頭の広告表記と、プライバシー＆免責事項ページのAmazon指定開示を維持する。

### 表のルール

- 表のセルは**全角20文字以内を推奨**（長いとPC幅で末尾1文字だけ折り返される）
- 表・図の下の補足注記は `<p class="table-note">※…</p>` で書く（CSSは定義済み）

### 末尾案内（既定の中立2段落・全文）

コード側の共通データは `scripts/article-footer.json`（`thanks`・`notice`）。既定では商品紹介やリンクを付けない。
案内文や選定の変更は、原本（CLAUDE.md）を先に更新し、共通データ／記事別案内・対象記事の本文ソース・関係する要約文書を一致させる。

```text
最後まで読んでいただき、ありがとうございます。

※商品リンクにはアフィリエイト広告を利用しています。リンク経由の購入が条件を満たすと、当ブログが紹介料を受け取る場合があります。
```

### 記事別案内（明示選択・個別確認した場合のみ）

- `scripts/article-footer-guides.json` は確認済み案内の許可リスト。記事のslugをキーとし、`intro`（紹介文）・`linkText`（リンク表示文）・`href`（リンク先）・`reason`（その記事で案内する選定理由）・`evidence`（根拠となる本文の原文文字列の配列）を持たせる。
- `evidence` は末尾案内より前の本文に文字どおり存在する記述とする。カテゴリ・タグ・推測や、案内文自体を根拠にしない。
- 明示選択した記事だけは、原稿と `src/content/blog/[slug].md` の記事本文ソースにも **お礼 → `intro` → `[linkText](href)` → 広告開示** の一致する4段落を記載する。設定だけで自動挿入される前提にしない。
- Word・Google Docsも選択済み案内と一致させ、リンクをクリック可能にする。サイト内の相対URLは `https://kakifoi.net` を補い、トップページへのリンクを一律には付けない。

### 原稿を渡す前の末尾チェック

- 直前に区切り線があり、既定では上記の中立2段落の全文だけが原稿に入っている。
- 記事別案内を明示選択した場合のみ、4段落が登録内容と一致し、`reason`・本文の原文と一致する `evidence`・リンクの表示文とリンク先を確認した。Word・Google Docsでもクリック可能なハイパーリンクになっている。
- 全記事共通のグリル・お肉への誘導や「別の商品を買ってもブログの応援になる」「リンク先の商品を買わなくてもOK」などの旧誘導が残っていない。
- 末尾の現行案内とは別に、旧案内や不要な広告注記を重複して追加していない。

## 投稿依頼文テンプレート

Chatで原稿を仕上げたら、以下の形式で投稿依頼文を作る。

検品と画像変換はCode側の共通手順なので、毎回の依頼文にコマンドや細かな検品工程まで書かなくてよい。
新規記事の公開後は、ブログ村用RSSの確認・承認済み公式IP限定許可の確認・「最新記事の取得」1回・反映確認も共通の必須ルーティンに含む。取得指示を毎回追記する必要はない。2026-10-30以降はkakifoi.netだけの公式IP Allowを使い、Bot Fight ModeをONのまま取得するのが通常運用。既存許可が正常なら、一時OFFの確認やAPIトークン発行を毎回求めない。許可の新規作成・変更・対象拡大は別途承認が必要で、未反映でも無断で保護を切り替えない。ブログ公開とブログ村の反映結果は分けて報告する。詳細は `.claude/PM-HANDOFF.md` を参照する。
公開ビルドで大きなJPEGの表示用画像・寸法・遅延読み込みを自動で整える。記事原稿は従来どおり元画像を指定し、元画像は保持する。詳細はCLAUDE.mdを参照。
記事固有の画像位置、トリミング上の要望、個人情報処理などは省略せず書く。

```
■元原稿: （原稿本文 or 添付ファイル名）
■カテゴリ: （固定7種から1つ）
■タグ: （既存タグ優先・新規は2記事以上見込みのみ）
■投稿日: （例: 2026-07-03 12:00 JST）
■スラッグ: （例: example-article-2026）
■本文中の画像: （枚数と、どのプレースホルダーにどの画像かの対応）
■アイキャッチ(1200×675): （元画像ファイル名。16:9センタークロップ→リサイズ）
■アフィリエイト案内文: 中立2段落（既定）を挿入し、区切り線・全文・旧誘導なしを照合済み／明示選択・個別確認済みの記事別案内4段落（対象slug・reason・evidence・登録内容・リンク先を照合済み）
■商品カード: あり（商品名・リンク）／なし
デプロイまでお願いします。
```
